# 06 — Build and dev setup

The canonical build/run instructions live in
[`README.md`](../README.md#build-and-run). This doc covers the parts that
don't fit there: the dual-compile mechanics, what each script does, and
the gotchas worth knowing before reaching for `git blame`.

## Workspaces

| workspace | members                                              | manifest                                       |
|-----------|------------------------------------------------------|------------------------------------------------|
| Cargo     | `server/`, `runtime/`, `blocks/`, `blocks-macros/`   | [`Cargo.toml`](../Cargo.toml)                  |
| pnpm      | `web/`, `tools/*`                                    | [`pnpm-workspace.yaml`](../pnpm-workspace.yaml)|

`tools/*` is declared but currently empty. `target/` and `web/build/` are
gitignored.

## Dual-compile: `runtime/` and `blocks/`

Both crates declare `crate-type = ["rlib", "cdylib"]` so the same source
links into `ferrited` natively *and* compiles to a wasm-pack package the
browser loads.

### `blocks/` features

[`blocks/Cargo.toml`](../blocks/Cargo.toml):

| feature   | enables                                                                |
|-----------|------------------------------------------------------------------------|
| `wasm`    | `wasm-bindgen` + `serde-wasm-bindgen` + `serde_bytes` + `js-sys` glue. |
| `soapysdr`| Links `libSoapySDR`; registers the `SoapySource` block. Native only.   |

`ferrited` enables `soapysdr` in its dependency line. The browser build
enables `wasm`. They are mutually exclusive in practice — building
`SoapySource` for `wasm32` will fail at monomorphization (as designed).

### `runtime/` features

[`runtime/Cargo.toml`](../runtime/Cargo.toml):

| feature | enables                                              |
|---------|------------------------------------------------------|
| `wasm`  | `wasm-bindgen` + the `wasm.rs` `RuntimeHandle` facade |

Native build (used by `ferrited`) is the default; the WASM facade
(`runtime/src/wasm.rs`) is `#[cfg(feature = "wasm")]`.

## WASM build pipeline

Driven from [`web/package.json`](../web/package.json):

```jsonc
"wasm:build:blocks":  "wasm-pack build --release --target web ../blocks  --out-dir ../web/src/lib/wasm/blocks  -- --features wasm",
"wasm:build:runtime": "wasm-pack build --release --target web ../runtime --out-dir ../web/src/lib/wasm/runtime --out-name runtime -- --features wasm",
"wasm:build":         "pnpm wasm:build:blocks && pnpm wasm:build:runtime",
"build":              "pnpm wasm:build && vite build"
```

Outputs land in `web/src/lib/wasm/{blocks,runtime}/`. Both directories are
gitignored — they are regenerated by `pnpm build` (or any of the
`wasm:build:*` scripts).

The runtime has `--out-name runtime` so the generated JS module is
`runtime.js` rather than `ferrite_runtime.js`; the runner imports it as
`import init, { RuntimeHandle } from '$lib/wasm/runtime/runtime.js'`.

Vite handles the rest via [`vite-plugin-wasm`](https://www.npmjs.com/package/vite-plugin-wasm)
+ [`vite-plugin-top-level-await`](https://www.npmjs.com/package/vite-plugin-top-level-await),
both wired in [`web/vite.config.ts`](../web/vite.config.ts) and re-applied
to the worker bundle (the runner Worker also needs WASM imports).

## SoapySDR via the local prefix

[`scripts/build-soapysdr.sh`](../scripts/build-soapysdr.sh) clones
SoapySDR + SoapySDRPlay3 + SoapyHackRF + SoapyRTLSDR into
`./soapysdr-src/` and installs them to `./soapysdr/` (no `sudo`, no
distro-package version skew). It writes `soapysdr/env.sh`:

```bash
export SOAPY_SDR_ROOT=/path/to/ferrite/soapysdr
export PATH=$SOAPY_SDR_ROOT/bin:$PATH
export LD_LIBRARY_PATH=$SOAPY_SDR_ROOT/lib:$LD_LIBRARY_PATH
export PKG_CONFIG_PATH=$SOAPY_SDR_ROOT/lib/pkgconfig:$PKG_CONFIG_PATH
export SOAPY_SDR_PLUGIN_PATH=$SOAPY_SDR_ROOT/lib/SoapySDR/modules0.8-3
```

`PKG_CONFIG_PATH` is what the `soapysdr` Rust crate's build script reads;
`SOAPY_SDR_PLUGIN_PATH` is what `libSoapySDR` reads at runtime to find
driver `.so` files. Source `soapysdr/env.sh` in any shell that runs
`cargo build -p ferrited`, `cargo test`, or `ferrited` itself.

The system distro packages (`libsoapysdr-dev`, `soapysdr-module-rtlsdr`)
also work, but the local prefix is the path the project actually develops
against and what gets driven by the daily test loop.

## Cross-origin isolation (COOP/COEP)

Required for `SharedArrayBuffer`, which is what carries audio between the
runner Worker and the AudioWorklet
([`web/src/lib/audio/ringBuffer.ts`](../web/src/lib/audio/ringBuffer.ts)).
Without it, the audio path silently goes mute.

Set in two places:

- **Dev:** [`web/src/lib/vite/coop-coep.ts`](../web/src/lib/vite/coop-coep.ts)
  via a Vite plugin that adds `Cross-Origin-Opener-Policy: same-origin` and
  `Cross-Origin-Embedder-Policy: require-corp` to every dev-server response.
  Also applied to `vite preview`.
- **Prod:** [`server/src/main.rs:313-314`](../server/src/main.rs) attaches
  the same headers to every response from `tower_http::ServeDir`.

Verify with `crossOriginIsolated === true` in the browser console (or
`curl -I http://localhost:5173/` and look for both headers).

## Toolchains

- **Rust** — current stable. `Cargo.toml`'s `rust-version = "1.89"` is the
  MSRV.
- **Node** — ≥ 20.10 (engines field in `package.json`); CI uses Node 22.
- **pnpm** — 10.33.0, pinned by `packageManager` in `package.json`. Older
  pnpm will refuse to install.

## Pre-commit hooks

[`lefthook.yml`](../lefthook.yml) installs hooks via `pnpm install`'s
`prepare` script. On commit:

| glob                                              | runs                  |
|---------------------------------------------------|-----------------------|
| `*.rs`                                            | `cargo fmt --all -- --check` |
| `*.{ts,tsx,js,mjs,cjs,json,md,svelte,yml,yaml,css}` | `pnpm -r lint`      |
| `*.{ts,tsx,svelte}`                               | `pnpm -r check`       |

`cargo clippy` and the workspace test run are deferred to CI — see
[05-testing.md](05-testing.md).

## Troubleshooting

**`Failed to open device: Resource busy`** — another process has the SDR.
Likely culprits: another `ferrited`, `rtl_test`, or the kernel
`dvb_usb_rtl28xxu` driver. `lsof /dev/bus/usb/...` and `lsmod | grep dvb`.

**`crossOriginIsolated === false` / no audio** — COOP/COEP missing on a
response. Check the browser network tab; both headers must be on the
HTML response and on every asset.

**`error: linking with `cc` failed: PKG_CONFIG_PATH …`** — building
`ferrited` without sourcing `soapysdr/env.sh`. Source it and rebuild.

**`SDRplay device not found`** — the SDRplay `sdrplay_apiService` daemon
isn't running. `systemctl status sdrplay`. The vendor `.run` installer
sets up the unit; it must be active before `SoapySDRUtil --find` shows
the device.

**`wasm-pack` errors about `rust-lld`** — install `lld`
(`sudo apt install lld`) or `rustup component add llvm-tools-preview`.

**Web build complains about missing `$lib/wasm/runtime/runtime.js`** — the
WASM packages haven't been built. Run
`pnpm --filter @ferrite/web wasm:build` (or just `pnpm --filter @ferrite/web
build`, which chains it).
